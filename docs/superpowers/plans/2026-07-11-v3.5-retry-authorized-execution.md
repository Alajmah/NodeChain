# Governed Retry-Authorized Side-Effect Execution (v3.5.0) Implementation Plan

**Goal:** Implement governed retry-authorized side-effect execution. An operator who previously issued `safe_to_retry` (v3.3) can now execute that retry through `EXECUTE_RETRY_AUTHORIZED`, producing a child attempt that enters the normal side-effect lifecycle (`planned → started → completed | failed | unknown`). The original `retry_authorized` row remains immutable history. The child uses a deterministic key, is gated by a recovery-specific runtime interceptor at the actual adapter dispatch boundary, and its outcome does NOT mutate chain state. Capsules are persisted proactively at original dispatch time so retry material exists when needed.

**Architecture:** Six layers. (1) **Schema + migration**: lineage columns + capsule table + recovery_execution_actions table + key table + capsule_status + indexes; remove `retry_authorized → started` from `LEGAL_TRANSITIONS`. (2) **Capsule system**: key hierarchy (KEK → DEK → capsule), proactive replay capsule persistence at `started` time via one authoritative store operation, inline SQLite, AES-256-GCM. (3) **Adapter identity + dispatch interceptor**: adapter version/attestation model, guarded adapter proxy that intercepts the real `search()` boundary. (4) **Coordinator + envelope + lineage**: `SideEffectRetryCoordinator`, `RecoveryEnvelopeV1`, deterministic lineage, fencing/heartbeat, atomic child/action allocation. (5) **RecoveryService + parent immutability**: pre-durable action path, transactional parent-lineage guard, recovery-only CAS repair, governance profile wiring, batch exclusion. (6) **CLI + lineage projection + metrics + deletion gate**: recovery-specific CLI composition, derived lineage states, reconciler, operational metrics, deletion/purge gate.

**Design basis:** `docs/design/retry-authorized-execution.md` (48-point lock, 5 review rounds). **Invariants:** `invariants/v3.5.md` (INV-001 … INV-022).

**Tech Stack:** Python 3.11+, sqlite3, Click CLI, pytest, cryptography (already a dependency), packaging (add as direct dependency for semver range matching). No other new dependencies.

## Locked non-goals
No autonomous retry scheduling · no policy-engine-triggered execution · no general RETRY_STEP redesign · no normal resume bypass · no arbitrary whole-node replay · no high-impact retries without idempotency · no multiple children from one decision · no downstream chain routing · no changing original retry_authorized row · no validator relaxation · no ancillary governed effects · no provider reconciliation · no authorization expiry/revocation · no capsule backfill for legacy rows · no batch retry execution.

## Implementation guardrails (from design review + plan review)
- **Remove the dead transition.** `retry_authorized → started` removed from `LEGAL_TRANSITIONS` in both `stores.py:208` and `state.py:931`. (INV-008)
- **Capsule is proactive, not reactive.** Written transactionally with `planned → started` for every governed side effect via one authoritative store operation covering BOTH started paths. If capsule write fails, the effect does NOT become started. (INV-004)
- **Pre-durable action path.** EXECUTE_RETRY_AUTHORIZED records action intent + child planned row + SIDE_EFFECT_RETRY_ATTEMPT_CREATED BEFORE external execution. Uses a new `recovery_execution_actions` table (not extending `operator_action_log`). (INV-018)
- **Parent permanently immutable.** Enforced transactionally in the store before the coordinator becomes reachable through RecoveryService. (INV-003)
- **No capsule in the envelope.** Envelope carries capsule reference; runtime gate loads from SQLite and verifies digest. (DEC-005)
- **Gate intercepts the real dispatch boundary.** A `RecoveryDispatchGuard` wraps the actual adapter at the `search()` boundary — NOT a pre-call journal gate. The journal runs before node execution and cannot mediate adapter calls that happen during execution. (Plan review Blocker 1)
- **Key hierarchy.** Master key (KEK) → per-run DEK → capsule. Missing master key on upgrade must NOT break ordinary search runs — capsules mandatory only for governed side effects under v3.5; default provisioning path required. (Plan review Blocker 3)
- **Recovery-only CAS repair.** Do NOT add `started → planned` to general `LEGAL_TRANSITIONS`. Use a dedicated fenced CAS repair operation for recovery children only. (Plan review sequencing correction)
- **Batch exclusion.** EXECUTE_RETRY_AUTHORIZED rejected by batch execution in v3.5. (Plan review additional item)

  ```
  Recovery node invocation
  ```

  - Rejects rescue-path secondary adapter calls before wire dispatch.
