# Retry Recovery Success Invariant (v3.2.0) Implementation Plan

**Goal:** Enforce the retry-recovery success invariant. A recovery result may advance execution only when (1) `recovered=True` + response present + `response.success=True`, OR (2) `recovered=True` + action in the narrow skip-continue allowlist. All other `recovered=True` shapes fail the chain.

**Invariant (design-note wording):** A recovery result may advance execution only when one of these is true: (1) recovered=True and response is present and response.success=True; (2) recovered=True and action is an intentional skip/continue action explicitly allowlisted. All other recovered=True shapes are invalid and must fail the chain rather than feed downstream output.

**Orchestrator guard (locked, two if-blocks):**
```python
if result.recovered and result.response is None:
    if result.action not in _SKIP_CONTINUE_ACTIONS:
        self._record_last_failure(...); self._fail_chain(...); return self.trace
if result.recovered and result.response is not None and not result.response.success:
    self._record_last_failure(...); self._fail_chain(...); return self.trace
```

**Skip-continue allowlist (narrow):** `_SKIP_CONTINUE_ACTIONS = {"skip_memory_write_policy_rejection", "trace_fallback_stderr"}`. The failed-response guard is UNCONDITIONAL — no action exempts a failed response.

**Action strings:** `schema_failure_retry_failed`, `model_timeout_retry_failed`, `search_unavailable_retry_failed`, `unknown_retry_failed`.

**Scope:** IN — four handler fixes + orchestrator run/resume guards + tests + docs/version bump 3.1.0→3.2.0. OUT — side-effect validator relaxation, recovery authority, operator RecoveryAction, unknown→completed, Model B.

**Non-negotiable:** skip exemption stays narrow; no exempting failed responses; no inferring success from recovered=True; no touching side-effect completion validation.
