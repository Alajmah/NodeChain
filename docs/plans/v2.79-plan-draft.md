## What the verification proved (correcting the original proposal)

The original proposal assumed `cli/main.py` was a behavioral monolith that "defines command handlers inline and ignores sibling modules." **That is false.** The verification established:

1. **Logic extraction is already done.** `main.py` (6,068 lines) does 154 lazy `from nodechain.cli.<sibling> import ...` delegations into ~30 sibling modules (`recover.py`, `run.py`, `dashboard.py`, `evidence.py`, `trust_store.py`, etc.) that hold the real implementation. The `run` command is representative: 14 Click options + one-line `asyncio.run(run_chain(...))`.
2. **What remains in main.py is the Click declaration shell** — 532 `@click.option` + 47 `@click.argument` + 12 `@cli.command` + 21 `@cli.group` + ~156 subcommand decorators (~168 command endpoints total). The siblings export plain functions, NOT Click objects, so the relocation target is "move decorators + thin delegation bodies," not "import existing groups."
3. **The two truth-drift fixes are real:**
   - `scripts/validate_schemas.py` L28/L33: `print("✅ ...")` / `print("❌ ...")` with NO encoding guard. Real `UnicodeEncodeError` crash on default Windows cp1252 stdout — a successful validation run crashes at the final line. Not cosmetic.
   - `VISION.md` L168: §6 reference-chains table still says the Research & Decision Assistant is "mock-tested, not yet run end-to-end with real adapters" — directly contradicts §13/§14/§16 which correctly state the v2.68 GLM-4.6 run succeeded. One stale table cell.

```text
  recover.py                 # implementation logic (unchanged)
  dashboard.py               # implementation logic (unchanged)

    audit_bundle.py

    evidence.py              # Click declarations + lazy delegation (imports from cli/evidence.py)
```

Pattern per module:
```python
@click.group("evidence")
def evidence_group():
    ...

@evidence_group.command("show")
@click.option(...)
def show(...):
    from nodechain.cli.evidence import show_evidence  # LAZY import preserved
    return show_evidence(...)

def register(cli):
    cli.add_command(evidence_group)
```

`main.py` does only:
```python
from nodechain.cli.commands import evidence, dashboard, audit_bundle, release_history
evidence.register(cli)
dashboard.register(cli)
...
```

## validate_schemas.py fix preference

Use **ASCII-safe output** over stdout reconfiguration:

```python
SUCCESS_MARK = "[OK]"
ERROR_MARK = "[ERROR]"
```

This avoids surprising console mutation and keeps the script portable under
default Windows stdout. Reconfiguring stdout to UTF-8 is acceptable but ASCII
output is the lower-risk fix for a validation script.
