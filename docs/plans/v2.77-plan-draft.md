# v2.99.0 Plan — Privileged Linux Native Sandbox Verification Harness

**STATUS: AGREED with ChatGPT. Privilege-boundary refinements folded in. Ready to execute.**

**Release thesis:** prove that the v2.76 native sandbox command-runner path
actually *enforces* confinement under its required privileged Linux execution
profile, with the proof scripted and repeatable. v2.76 showed the path is
wired; v2.77 shows it is enforcing (under privilege). This retires the single
material caveat v2.76 carries.

**Renamed from "CI-gated" → "Privileged" (ChatGPT refinement, accepted):** the
verification runner requires `CAP_SYS_ADMIN`/`CAP_SYS_CHROOT`, which the GHA
runner user (`gha-runner`, uid 1000) does not have. Enforcement is therefore
verified under a privileged execution profile (root on the verification host),
NOT inside the GHA job context. GHA-native non-root execution is deferred.

Validate-before-extend. Docker is **not** in scope.

**ChatGPT's earlier refinement (accepted):** v2.77 must not rely on metadata
alone where child-observed proof is available. The enforcement tests must
observe confinement *from inside the sandbox*, not merely assert that the runner
*reported* confinement. Metadata-reported booleans can lie; a child that
actually reads `/workspace/sentinel.txt` and actually fails to open a socket
cannot.

**ChatGPT's operational caveat (accepted, the most important v2.77 caveat):**
the current native_os_sandbox backend requires privileges that ordinary
non-root CI users and many production service users do not have. v2.77 verifies
enforcement under the privileged profile, but does NOT prove that
sandbox_test_runner can run from an unprivileged deployment account.
Unprivileged-native execution is future work and a production-readiness
requirement before relying on this backend in non-root service deployments.

**Privilege-dependent capability matrix (the key finding):**

| Operation | as root | as gha-runner (uid 1000, GHA runner) |
|---|---|---|
| `unshare --mount --pid --fork` | ✅ OK | ❌ "Operation not permitted" |
| `unshare --user --map-root-user --mount --pid --fork` | ✅ OK | ❌ "Permission denied" (userns blocked in LXC) |

cannot execute the native path. This is not a setup gap; it's a privilege
boundary that defines the release scope.

## The precise thing v2.77 proves (and does NOT prove)

**Proves:** the integrated v2.76 command-runner chain enforces confinement
end-to-end on Linux **under the privileged execution profile the current
implementation requires**:

```
SandboxCommandRunner("native_os_sandbox").run_command(argv, cwd, ...)
  → native_sandbox_exec.run_isolated(...)
    → child bootstrap: PID ns → network ns → mount ns
                       → mount confinement (with workspace_src → /workspace)
                       → seccomp filter
    → subprocess.run(argv, shell=False) UNDER enforcement
  → result.sandbox_metadata reports per-primitive enforcement
  → adversarial: outbound connection is blocked
```

**Does NOT prove (out of scope):**
- kernel-exploit resistance, container-escape resistance, compromised-daemon
  resistance, formal security-boundary proof. v2.77 is enforcement
  verification of an existing code path against a real Linux kernel, not a
  security proof. No "complete hostile-code containment" claim.
- **GHA-native execution.** The GHA runner user cannot execute the native path.
  v2.77 does not claim enforcement inside the GHA job context.
- **Unprivileged/production deployment.** v2.77 does not prove the backend can
  run from a non-root service account. That is a production-readiness
  requirement for future work (option 2: enable unprivileged userns + adapt
  the bootstrap).

**Does NOT duplicate:** the existing primitive tests
(`test_namespace_confinement.py`, `test_mount_confinement.py`,
`test_seccomp_productization.py`, etc.) already validate the *primitives* in
isolation. v2.77 validates the *integration through the v2.76 seam*. Both
layers are needed; neither substitutes for the other.

## Gate semantics (three-tier, per ChatGPT's privilege-aware revision)

```
Tier 1 — Normal developer hosts (incl. Windows, macOS, dev Linux):
  native_sandbox tests SKIP unless explicitly enabled.
  Reason: local portability. Suite stays green everywhere.

Tier 2 — Designated Linux verification host, run AS ROOT
  (NODECHAIN_NATIVE_RUNNER=1 + uid 0):
  native_sandbox tests MUST RUN and MUST assert enforcement.
  missing capability = hard failure, never skip.
  mount confinement: metadata True + child-observed /workspace behavior.
  network namespace: metadata True + host positive control + sandbox block.
  seccomp: metadata True + denied-syscall canary if feasible.
  skip is NOT acceptable release evidence in this tier.

Tier 3 — Inside GHA as gha-runner (non-root):
  v2.77 does NOT claim native enforcement execution here.
  a GHA job may invoke documentation checks or non-enforcement tests only.
  the enforcement tests skip in this tier (gha-runner cannot run them).
```

**Mechanism (agreed): single marker + env var.** No second marker.

```
@pytest.mark.native_sandbox     # marks the test
NODECHAIN_NATIVE_RUNNER=1       # flips tier-1 skip → tier-2 run+enforce
```

- Register `native_sandbox` marker in `pyproject.toml`.
- `tests/conftest.py` hook: a `native_sandbox`-marked test skips unless
  `platform.system() == "Linux"` AND `NODECHAIN_NATIVE_RUNNER=1`.
- The release path is the helper script (Sequence step 6), which asserts
  `uid 0` as one of its fail-closed preconditions (Tier 2, not Tier 3).

### 3. Write the load-bearing enforcement test
`tests/test_native_sandbox_enforcement.py`, marked `native_sandbox`.

**ChatGPT refinement (accepted): metadata is necessary but NOT sufficient. Each
primitive must also be proven by child-observed evidence where feasible.**

```python
def test_native_command_path_enforces_mount_confinement(tmp_path):
    """Prove mount confinement via child-observed evidence, not metadata alone."""
    # Write a sentinel into the workspace BEFORE running — the confined child
    # must be able to read it at /workspace/sentinel.txt.
    (tmp_path / "sentinel.txt").write_text("workspace-visible")
    runner = SandboxCommandRunner("native_os_sandbox")
    probe = (
        "import sys; "
        "open('/workspace/sentinel.txt').read()"  # succeeds → prints nothing, exits 0
    )
    res = runner.run_command(
        argv=[sys.executable, "-c", probe],
        cwd=tmp_path, timeout_seconds=30, max_output_bytes=50_000,
    )
    meta = res.get("sandbox_metadata", {})
    # Metadata claim
    assert meta.get("mount_confinement_enforced") is True
    assert "/workspace" in meta.get("allowed_mounts", [])
    # Child-observed proof: the read succeeded (exit 0) → workspace really is mounted
    assert res["exit_code_interpretation"] == "pass", (
        f"child could not read /workspace/sentinel.txt; stderr={res['stderr'][:300]}"
    )
```

### 4. Write the adversarial network-blocking test
**ChatGPT refinement (accepted): host positive control.** The test must prove
the host *can* reach the target before proving the sandbox *blocks* it —
otherwise "blocked" might just mean "the runner has no network."

```python
def test_native_command_path_blocks_outbound_network(tmp_path):
    target = os.environ.get("NODECHAIN_NATIVE_SANDBOX_NET_TARGET", "1.1.1.1:53")
    host, port = target.split(":")
    # Positive control: host must be able to reach the target unsandboxed.
    import socket
    try:
        socket.create_connection((host, int(port)), timeout=3).close()
    except OSError as e:
        pytest.fail(
            f"host positive-control failed: cannot reach {target} ({e}); "
            "runner is misconfigured for this test — 'blocked' would be meaningless"
        )
    # Adversarial: same target must fail inside the native sandbox.
    runner = SandboxCommandRunner("native_os_sandbox")
    probe = f"import socket; socket.create_connection(('{host}', {port}), timeout=2)"
    res = runner.run_command(argv=[sys.executable, "-c", probe], ...)
    assert res["exit_code_interpretation"] != "pass"  # connection did NOT succeed
    assert res["sandbox_metadata"]["network_namespace_enforced"] is True
```

Target is configurable via `NODECHAIN_NATIVE_SANDBOX_NET_TARGET` (default
`1.1.1.1:53`). Use the real external target, not loopback — loopback proves
namespace separation but not egress denial convincingly.

### 4b. Seccomp canary (if feasible)
Where a denied-syscall canary is clean (a syscall from the actual deny list
that would otherwise succeed), include it so the seccomp proof is active, not

### 5. Run on the runner; fix what surfaces in `native_sandbox_exec.py`

## Acceptance criteria

v2.99.0 is shippable only if ALL are true:

```
1.  On root@192.0.2.100 with NODECHAIN_NATIVE_RUNNER=1:
    the native_os_sandbox command-runner path executes argv through the full
    child bootstrap and returns sandbox_metadata reporting per-primitive
    enforcement.
2.  mount_confinement_enforced=True is asserted on the runner (not skipped).
3.  network_namespace_enforced=True is asserted on the runner.
4.  seccomp_enforced=True is asserted on the runner.
5.  /workspace appears in allowed_mounts when workspace_src is provided.
6.  CHILD-OBSERVED mount proof: the confined child can read
    /workspace/sentinel.txt (a file placed in the host workspace before the
    run). Metadata-only does NOT satisfy this criterion.
7.  Outbound network connection is BLOCKED under the native path
    (adversarial test passes on runner), AND the host positive-control
    (unsandboxed reach to the same target) succeeds first. "Blocked" must
    mean the sandbox blocked it, not that the runner had no network.
8.  On the Windows dev host and on .28 WITHOUT the flag: the same tests
    SKIP for portability. Suite stays green (6,159+ passed).
9.  Missing capability on the runner FAILS the test, never silently skips.
10. No Docker code ships in v2.77.
11. No changes to local_subprocess backend behavior.
12. No new sandbox primitives added.
13. CGROUPS — be explicit: either (a) claim cgroup enforcement and prove it
    via metadata + a small runtime probe, OR (b) docs/release notes state
    cgroup v2 was present on the runner but cgroup enforcement was NOT part
    of the v2.77 release claim. "cgroup2fs exists" is NOT acceptable as
    implied proof of enforcement.
14. SECCOMP — either include a denied-syscall canary (active proof), OR
    document that v2.77 proves seccomp installation/reporting only and the
    canary is deferred. "seccomp_enforced=True metadata" alone is not
    acceptable as the only seccomp evidence without acknowledging the gap.
15. scripts/run_native_sandbox_verification.sh fail-closes on its own
    preconditions: flag unset, non-Linux, zero tests collected, tests
    skipped, seccomp package absent, host positive-control failure →
    script exits non-zero. No green-looking run that verified nothing.
16. docs/native_sandbox_verification.md documents the repeatable procedure
    AND states the honest scope (enforcement verified, not security proof).
17. Full suite passes on both hosts: green-with-skips on Windows,
    green-with-enforcement on .28.
18. Any fixes to native_sandbox_exec.py are minimal, localized, and preserve
    the v2.76 seam. "2–4 fixes" is an expectation, NOT an acceptance
    criterion — real Linux may surface zero or one structural edge case.
```

## Verification script fail-closed (ChatGPT refinement #3, accepted)

`scripts/run_native_sandbox_verification.sh` must exit non-zero if ANY of:
- `NODECHAIN_NATIVE_RUNNER` is not set
- **not running as root (uid 0)** — required for the privilege profile (v2.77 refinement)
- platform is not Linux
- the required `native_sandbox` tests are skipped or not collected
- native capabilities are missing (probe before running)
- the `seccomp` Python package is absent
- the host positive-control network check fails

This prevents a green-looking release run that did not actually verify anything.

   the runner having the route blocked at the namespace, not at a firewall.

   `native_sandbox_exec` passes `workspace_src=str(cwd)`. Confirm the
   integration test should pass a real temp workspace and assert its bind-mount
