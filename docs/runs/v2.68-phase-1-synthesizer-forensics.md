# Phase 1: Evidence Synthesizer Forensic Debug

**Date:** 2026-07-01
**Run analyzed:** `62008aa6-4133-4423-a033-8e99268a1526` (first real chain run)
**Status:** Root cause found — no synthesizer code fix needed

---

## Root Cause: LIMModelAdapter Prompt Truncation

The first real chain run used the pre-fix `LIMModelAdapter` for the
`openai_compatible` provider path (fixed in v2.67.1). That adapter has a
`truncate_for_context()` method that truncates prompts to fit the model's
context window.

### The truncation bug

| Parameter | Value |
|-----------|-------|
| Synthesizer requests | `max_tokens=10240` |
| LIMModelAdapter truncation uses | `max_output_tokens=4096` (default, ignores caller's request) |
| Model context window (Gemma 4 12B) | ~8192 tokens |
| Truncation budget | `8192 - 4096 - 512 = 3584 tokens ≈ 14,336 chars` |
| Actual synthesizer prompt | ~30,000 chars (8 sources × ~1300 char abstracts + JSON schema) |
| **Effective prompt after truncation** | **~14,336 chars — sources cut off mid-abstract** |

The model received truncated, garbled source data. It could not produce
structured claims from incomplete abstracts. The synthesizer's fallback
fired: `"Unable to synthesize evidence due to processing error."`

### Failure classification

**Adapter context truncation bug** — not model capability, not JSON parsing,
not schema mismatch, not prompt design.

---

## Isolation Test: Fixed ModelAdapter + Same Sources

Ran the synthesizer node in isolation with the SAME 8 top-quality sources
from the failed run, using the fixed `ModelAdapter` (which does NOT truncate).

### Configuration

| Parameter | Value |
|-----------|-------|
| Sources | Top 8 by quality score (from the 56 found in the real run) |
| Prompt source data | 21,557 chars |
| Full user message | 21,757 chars |
| Model | google/gemma-4-12b |
| Adapter | ModelAdapter (openai_compatible, no truncation) |
| max_tokens | 10,240 |
| temperature | 0.3 |

### Result

| Metric | Value |
|--------|-------|
| Content length | 1,559 chars |
| Output tokens | 1,611 |
| Latency | 32,839 ms (33 sec) |
| Structured output | Valid JSON |
| Claims produced | 3+ (with claim_id, statement, supporting_sources using correct S1-S8 aliases, confidence scores) |
| Synthesis | Summary with key findings |

**Conclusion:** Gemma 4 12B can synthesize valid claims from 8 academic
sources when given complete, untruncated input. The model is capable
enough for this task. The failure was caused by the adapter, not the model.

---

## What v2.67.1 Already Resolves

The adapter routing fix (using `ModelAdapter` instead of `LIMModelAdapter`
for `openai_compatible`) eliminates the truncation. `ModelAdapter` sends
the full prompt to the OpenAI-compatible endpoint without truncation.

## Additional Issue (Non-Blocking)

`ModelAdapter` has NO truncation at all. If a prompt exceeds the model's
actual context window, the API will reject it or truncate server-side.
This is acceptable for now because:
- The synthesizer already limits to top 8 sources (~21K chars, fits in 8K context)
- Other nodes have smaller prompts
- Should add graceful truncation to `ModelAdapter` as a future enhancement

---

## Phase 1 Conclusion

No code fix needed beyond v2.67.1. The root cause was the pre-fix adapter,
which is already replaced. Proceeding to Phase 4: full chain re-run with
the fixed adapter and same Gemma model to preserve causal clarity.
